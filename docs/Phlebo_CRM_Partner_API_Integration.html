2. End-to-end flow

1. Customer books home collection in your CRM.
2. CRM calls Phlebo POST /partner/orders with patient, address, slot, tests.
3. Order is saved in Phlebo and appears in Admin → Orders.
4. Phlebo Ops assigns a phlebotomist (or auto-assign may run).
5. Phlebotomist completes the visit in the Phlebo mobile app.
6. Phlebo notifies CRM via webhook on status changes (if configured).

3. Authentication — how CRM uses the Phlebo API

Phlebo Partner APIs do not use Admin login or Phlebo mobile OTP/JWT. CRM authenticates with the Partner API Key that Phlebo gives you (see credentials table above).

How to use it

  1. Phlebo creates a Client for your CRM and shares the API Key (starts with pk_live_).
  2. Your CRM server stores that key securely (environment variable / secrets vault — never in a mobile app or public frontend).
  3. On every Partner API call, your server sends the key in the request header.
  4. Phlebo checks the key, identifies your CRM client, and creates/reads only your orders.

Header (required on every request) — use one of these:

Authorization: Bearer pk_live_xxxxxxxxxxxxxxxx

OR

x-api-key: pk_live_xxxxxxxxxxxxxxxx

Example (Create order with auth)

POST https://phlebohub.razobyte.com/v1/api/partner/orders
Content-Type: application/json
Authorization: Bearer pk_live_xxxxxxxxxxxxxxxx

{ "externalOrderId": "CRM-ORDER-12345", "patientName": "...", ... }

If the key is missing or wrong, Phlebo returns HTTP 401. Do not use Admin passwords or Phlebo app login for these APIs.

Required fields

  • externalOrderId — your CRM unique order id (also accepts orderId)
  • patientName
  • address
  • slotDate — YYYY-MM-DD
  • slotTime — e.g. 09:00-10:00

Strongly recommended

  • mobileNumber, city, pincode, age or dob (YYYY-MM-DD)
  • lat, lng — improves auto-assign / routing
  • items, totalAmount / amount
  • paymentMethod, paymentStatus

Success (new order) — HTTP 201

{
  "success": true,
  "message": "Order created in Phlebo",
  "orderId": "<phlebo_order_id>",
  "order": { "...full order..." }
}

Duplicate same externalOrderId — HTTP 200

{
  "success": true,
  "message": "Order already exists",
  "orderId": "<phlebo_order_id>",
  "order": { "...existing order..." },
  "duplicate": true
}
After this call: the order appears in Phlebo Admin → Orders (usually status: Booked, phleboStatus: Unassigned unless auto-assigned). Ops can then assign a phlebotomist.

CRM RECEIVES API 6 — Status webhook (Phlebo → CRM)

This is not an API you call. Phlebo POSTs to your webhookUrl when order status changes (assign, collect, handover, payment, etc.).

Example request from Phlebo

POST https://your-crm.example.com/webhooks/phlebo
Content-Type: application/json
X-Phlebo-Signature: <hmac_sha256_hex>
X-Phlebo-Client: <client_slug>

{
  "event": "order.status_changed",
  "orderId": "<phlebo_order_id>",
  "jobId": "<same_as_orderId>",
  "externalOrderId": "CRM-ORDER-12345",
  "clientSlug": "your-crm-slug",
  "phleboStatus": "Sample Collected",
  "status": "Processing",
  "assignedPhleboName": "Yogesh",
  "assignedPhleboId": "...",
  "paymentStatus": "Paid",
  "paymentCollectedMethod": "UPI",
  "collectedAt": "...",
  "arrivedAt": "...",
  "items": [],
  "amount": 399,
  "totalAmount": 399,
  "samples": [{ "barcode": "...", "sampleType": "Blood" }],
  "updatedAt": "..."
}

Signature verification (recommended)

signBase = externalOrderId + "|" + jobId + "|" + phleboStatus + "|" + status
expected = HMAC_SHA256(webhookSecret, signBase) as hex
Compare expected with header X-Phlebo-Signature
